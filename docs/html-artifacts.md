# Static HTML reports

The document reader accepts self-contained `.html` reports alongside Markdown and text. The existing machine, Session, project/task scope and relative-path identity still govern every read; documents remain encrypted over Cloud. This format adds no operation, envelope field, protocol version or error code. Inline screenshots use the additional decoded-image bounds below.

Reports can use embedded CSS, static inline SVG, tables, and native `details`/`summary`. Scripts, forms, navigation and external resources are removed or blocked. Inline PNG and JPEG screenshots are supported through canonical `data:image/png;base64,...` and `data:image/jpeg;base64,...` sources on `img`. Multi-file sites and external images, fonts or scripts are outside this format. Use a responsive report and a horizontal scrolling wrapper for wide tables.

The daemon sanitizes HTML with pinned bluemonday and parses CSS with douceur. It keeps a static property/function allowlist, local SVG fragments and safe CSS variables. It rejects CSS resource values and resource at-rules. Image sources must use the exact MIME prefix and canonical, strictly decoded base64; whitespace, extra parameters, alternate schemes and other formats (including SVG and GIF) are omitted. Animated PNG is also omitted, so extra animation frames cannot exceed the decoded pixel budget. The daemon verifies the actual image format, checks dimensions before allocating pixels, then fully decodes it to reject malformed images. Invalid image elements are omitted while the rest of the report remains readable. The existing 2 MiB document byte cap applies before and after cleanup, including all embedded image data.

Each screenshot is limited to 8,192 pixels on either side and 16,777,216 decoded pixels. The report retains at most 67,108,864 decoded pixels in total, counting repeated images separately; later images beyond the remaining budget are omitted. These bounds are registered under `artifacts.report_image_side`, `artifacts.report_image_pixels` and `artifacts.report_total_image_pixels`. Reduce screenshot dimensions or split the report when needed; the document byte cap is unchanged. Markdown and text bytes keep their existing representation.

The console sanitizes received HTML again with pinned DOMPurify and renders it in an iframe with an empty sandbox, without script or same-origin privileges. The second sanitizer only retains canonical PNG/JPEG image data with matching bounded image headers, applies the same cumulative pixel budget, removes other image sources and strips resource-bearing CSS. The daemon remains responsible for full image decoding. A trusted CSP precedes report content: `img-src data:` permits embedded screenshots, while `default-src`, `connect-src`, scripts and other resource types remain denied. The report never enters the console DOM. Its title and metadata use text nodes. The direct HTTP document route also applies CSP sandbox and only allows data images in its otherwise restrictive resource policy; use the console preview for report styling.

A daemon from before inline screenshot support removes image elements; both the daemon and console must be updated to display embedded screenshots. A console that supports HTML with an older daemon that does not support HTML cannot read that format. An older console rejects the new MIME value conservatively; it does not gain HTML rendering. Deploy the console before enabling the daemon format. Existing Markdown and text continue to work. Rollback the console and daemon independently to compatible versions, retaining the report file for a later read.

Canonical HTML document locators are also accepted by Notes. Their machine, route Session, scope and relative-path checks remain the same as for Markdown and text; the Note links to the existing isolated document viewer. Other formats such as XHTML and JavaScript remain unsupported.

## Verification and measurements

The local browser fixture uses the real renderer and a real HTTP collector, in Chromium and WebKit at 390 and 1280 CSS pixels. It checks the report tables and native expansion, then attempts scripts, parent DOM access, navigation, popups and resource loads. The collector received zero requests. Chromium reports CSS attempts as failed with `csp`; a browser request event alone is not evidence of a request reaching a server.

The same sanitized report is 7,565 UTF-8 bytes and is fetched once in each sample. The original decoder rejects HTML, so its refusal cannot be compared with successful rendering as an efficiency improvement. Existing Markdown takes the same rendering path; short samples are frequently below the browser timer resolution and do not establish a speedup. Heap samples are coarse or unavailable and are not a memory-reduction claim.

Measured fetch, mount, ready times and raw Markdown samples are in [the browser record](performance/html-artifact-browser.json). `readyMs` includes browser automation waiting for the report table; it is not a production SLO. These samples are local component checks, not authenticated Cloud acceptance, an actual phone test or a capacity benchmark. Deployment, independent review and Cloud identity/revocation acceptance require separate evidence.

Authenticated production routing, offline recovery and machine-local pairing revocation are recorded in [Cloud acceptance](performance/html-cloud-acceptance.md), with their test boundaries stated separately from the component measurements.
