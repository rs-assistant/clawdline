# Local Cloud cost baseline completion

This baseline supplies repeatable local measurements and compatibility controls,
not a fleet capacity promise or a new production optimization. All workloads use
synthetic data and isolated services; paid external API requests are zero. The
parser candidate remains paused. No new product limit, protocol or error code is
introduced. The public evidence pages below retain source pins, actual samples,
CPU subjects, counter boundaries, independent review and unmeasured cells.

Schedule waiting, notification loss/restart and delivery semantics belong to the
separately completed scheduling optimization acceptance. Its matched synthetic
benchmark and observed deployment are not substituted for browser or fleet-load
measurements. Natural production traffic windows are not matched trials.

## Compatibility prerequisites for the next change

Before implementing a candidate, preserve exact content/session identity, advancing
sequence and replay rejection, receipt retention, duplicate idempotency, post-command
fresh reads, authority removal/restoration and same-client reconnect/fallback.
Use each workload's current controls and identical inputs on both revisions.
At least three matched/interleaved rounds must identify operation count, completion,
CPU subject, bytes boundary and observation window. A successful queue or relay ACK
alone is not viewer decode. Compare CPU totals within the same subject and window;
do not subtract combined-fixture CPU from isolated-machine CPU.

Measured ranges are baseline evidence rather than an invented production SLO.
Any new timing tolerance must be agreed and fixed before the candidate is changed.
The parser profile identifies a possible next hotspot, but its implementation is
explicitly paused. The terminal relay loop's existing polling cadence is another
local observation, not authorization to change its behavior or an optimization result.

## Explicit unmeasured boundaries

Production saturation, thousand-user capacity, WAN/NAT/TLS packet accounting, official
Cloud account revocation propagation, browser CPU, actual phone Safari and full tmux
client/server CPU are not measured by these local experiments. Sparse three-round
samples do not justify p95/p99 claims. The native fixture does not render the entire
React application. Existing missing cells remain visible in each page and do not
become passing measurements by closing this baseline-delivery work.

Capacity testing and authority-read optimization remain separate plans. No new
plan is claimed and no production load is generated by this completion. The outcome
is a reusable local baseline and explicit compatibility checks for later authorized
work, with normalized numeric evidence and Cloud-readable static HTML delivery.
