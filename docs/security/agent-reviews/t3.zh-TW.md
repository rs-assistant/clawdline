## Claude Code 的原文

**結論：** 這是知名開發者團隊（Ping.gg / Theo）的開源專案，我沒有查到它被植入惡意程式或有已公開的漏洞。不過我只看了 README 和官方文件，沒有逐行審查原始碼。真正的風險主要在它的預設設定和運作方式，不在「這個專案是假的」。

#### 已確認的情況
- **身分：** 官方 repo `pingdotgg/t3code`，有安全政策（回報到 [SECURITY.md 列出的信箱](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/.github/SECURITY.md)）。
- **漏洞紀錄：** GitHub Security 頁面寫著「沒有任何已發布的安全公告」，網路上也沒搜到相關漏洞報告。

#### 主要風險（依重要性排列）

1. **權限預設是「Full access」（最需要注意）**
   - 官方文件 `docs/user/permission-modes.md` 寫明，新對話的初始預設是 Full access：AI 代理可以直接執行指令、修改檔案，不會先問你。
   - 代理用的是你的使用者權限，所以可能讀到 `~/.ssh`、`.env`、雲端憑證這類檔案。若遇到 prompt injection（例如惡意 repo 或網頁裡藏了指令），後果會更嚴重。
   - 建議：到 Settings → General → New threads → Permissions，改成 **Supervised** 或 **Auto-accept edits**。

2. **安裝方式是 `curl | sh` 或 `irm | iex`**
   - 這等於直接執行網路上下載的腳本。
   - 另外，你給的是一個固定的 commit，但官方安裝腳本和 `npx t3@latest` 裝的是「最新版」，不是這個 commit。
   - 建議：先打開腳本看一下內容，或改用 GitHub Releases、Homebrew 安裝；想鎖定版本就從原始碼建置。

3. **遠端存取 / T3 Connect**
   - 預設只在本機可以連，這點是安全的。
   - 如果開啟 Network access、Tailscale 或 T3 Connect，流量會經過 T3 的雲端通道。
   - 配對時沒指定 `--scope` 的話，對方會拿到**全部權限**，包括終端機控制。
   - 配對連結的效力等同密碼，不要截圖或貼到別處。

4. **遙測預設會傳送**
   - 會傳到 `ingest.t3.codes`（再轉給 PostHog）和 Axiom，內容包括模型、token 數、權限模式，以及帳號的雜湊 ID 等。
   - 官方說明不會收集 prompt、回應、檔案內容和 token。
   - 關閉方法：在環境變數設定 `T3CODE_TELEMETRY_ENABLED=false`。

5. **早期軟體**
   - README 直接寫「Expect bugs」。
   - 它也會控制你已登入的 Claude Code、Codex 等 CLI，所以這些工具本身的風險也會一併帶進來。

#### 建議做法
- 處理敏感的工作或公司專案時，先把權限模式改成 Supervised。
- 不需要的話，不要開遠端存取和 T3 Connect。
- 如果要開，配對時用 `--scope` 限制權限。
- 不想傳遙測就關掉。
- 想更保險，可以在 VM、devcontainer 或另一個使用者帳號裡執行。

如果需要，我可以接著把安裝腳本抓下來，幫你看看它實際做了哪些事。

## Codex 的原文

**有風險。我不建議直接裝在存有正式環境金鑰、客戶資料的主力電腦上，以預設設定使用。** 可以先在隔離環境試用。

我檢查了你指定的 `7ffc3bb…` 版本文件與部分程式碼；以下是具體風險，並不代表已證實它是惡意軟體。

| 風險 | 查到的行為與影響 |
|---|---|
| **預設允許直接執行操作** | 新對話初始預設為 **Full access**，Agent 可執行命令、修改檔案而不跳確認。若被惡意 README、網頁內容誘導，可能直接造成損害。[權限文件](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/user/permission-modes.md) |
| **開啟專案不等於限制存取範圍** | 官方明確說專案不是檔案系統沙箱；`filesystem:read` 可讀取執行帳號有權讀取的專案外絕對路徑。因此同帳號的 `.env`、SSH 私鑰等也是潛在影響範圍。[認證邊界](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/internals/environment-auth.md) |
| **遠端配對權限很大** | 預設配對授權包含終端機與啟動 Full access Agent 的能力。文件也承認這些權限可進一步建立具完整權限的 session；手機或配對憑證遭入侵，可能連帶危及主機。[認證邊界](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/internals/environment-auth.md) |
| **預設有資料傳出** | Server 遙測預設開啟，事件送至 `ingest.t3.codes`，保留副本並轉送 PostHog。這不能直接推論它上傳原始碼，但不能視為完全離線工具。[遙測程式碼](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/apps/server/src/telemetry/AnalyticsService.ts) |
| **安裝內容可能不是你指定的版本** | README 推薦 `curl … \| sh` 與 `npx t3@latest`，執行的是當時下載到的內容，沒有固定到這個 commit。檢查此 commit 不等於驗證最新安裝包。[安裝說明](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/README.md) |

它也有安全設計：逐項 RPC 權限檢查、一次性配對及 DPoP 憑證綁定。不過官方明確承認，T3 Connect 的 relay 簽章金鑰仍是必須信任的環節；這些機制不代表雲端遭入侵也沒事。[授權程式碼](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/apps/server/src/auth/RpcAuthorization.ts)、[Connect 信任模型](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/internals/t3-connect.md)

若要試用，我建議：

- 用獨立 VM 或無敏感資料的 OS 帳號，只放測試專案。
- 將新對話預設改成 **Supervised**，並確認個別專案沒有覆寫。
- 先只用本機連線，關閉 Network access 與 T3 Connect。
- 固定版本、核對官方發佈檔的簽章或校驗資訊；避免直接執行浮動版本安裝指令。
- 若不接受遙測，Server 提供 `T3CODE_TELEMETRY_ENABLED=false`；這不會關閉 AI 供應商本身的連線。

**目前能支持的結論是：這是需要高度信任的主機控制工具，適合隔離試用，還不足以替敏感主力環境背書。** 本次未安裝執行、未完整掃描相依套件，也未驗證發佈二進位與原始碼一致性。
