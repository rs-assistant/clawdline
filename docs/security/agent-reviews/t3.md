## Claude Code (translated)

**Conclusion:** This is an open-source project from a well-known developer team (Ping.gg / Theo); I found no reports of malicious code planted in it and no published vulnerabilities. But I read only the README and the official documentation and did not review the source line by line. The real risk lies mainly in its default settings and how it works, not in "the project being fake".

#### What I confirmed
- **Identity:** the official repo is `pingdotgg/t3code`, with a security policy (report to [the address in SECURITY.md](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/.github/SECURITY.md)).
- **Vulnerability record:** the GitHub Security page says "there aren't any published security advisories", and I found no related vulnerability reports online.

#### Main risks (in order of importance)

1. **Permissions default to "Full access" (needs the most attention)**
   - The official document `docs/user/permission-modes.md` states that the initial default for new threads is Full access: the AI agent can run commands and modify files directly, without asking you first.
   - The agent runs with your user privileges, so it may read files such as `~/.ssh`, `.env` and cloud credentials. In a prompt-injection case (for example, instructions hidden in a malicious repo or web page) the consequences are more serious.
   - Recommendation: go to Settings → General → New threads → Permissions and change it to **Supervised** or **Auto-accept edits**.

2. **Installation is `curl | sh` or `irm | iex`**
   - This amounts to directly running a script downloaded from the internet.
   - Also, you gave a pinned commit, but the official installation script and `npx t3@latest` install the "latest version", not this commit.
   - Recommendation: open the script and look at it first, or install from GitHub Releases or Homebrew instead; to pin a version, build from source.

3. **Remote access / T3 Connect**
   - By default it can be reached only locally, which is safe.
   - If you enable Network access, Tailscale or T3 Connect, traffic passes through T3's cloud tunnel.
   - If you pair without specifying `--scope`, the other side gets **all permissions**, including terminal control.
   - A pairing link is as powerful as a password; do not screenshot it or paste it elsewhere.

4. **Telemetry is sent by default**
   - It goes to `ingest.t3.codes` (which forwards to PostHog) and Axiom, and includes the model, token counts, permission mode, a hashed account ID and so on.
   - The official description says prompts, responses, file contents and tokens are not collected.
   - To turn it off: set the environment variable `T3CODE_TELEMETRY_ENABLED=false`.

5. **Early-stage software**
   - The README says outright "Expect bugs".
   - It also controls the Claude Code, Codex and other CLIs you are signed in to, so those tools' own risks come along too.

#### Recommended approach
- For sensitive work or company projects, first change the permission mode to Supervised.
- If you do not need them, do not enable remote access or T3 Connect.
- If you do enable them, restrict permissions with `--scope` when pairing.
- If you do not want to send telemetry, turn it off.
- To be safer, run it in a VM, a devcontainer or another user account.

## Codex (translated)

**There is risk. I do not recommend installing it directly, with default settings, on a main computer that holds production keys or customer data.** It can be tried first in an isolated environment.

I examined the documentation and part of the code of the `7ffc3bb…` version you specified; the following are concrete risks and do not mean it has been shown to be malware.

| Risk | Behaviour found and its impact |
|---|---|
| **Operations allowed directly by default** | The initial default for new threads is **Full access**: the Agent can run commands and modify files without a confirmation prompt. If misled by a malicious README or web content, it may cause damage directly. [Permissions documentation](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/user/permission-modes.md) |
| **Opening a project does not limit what can be accessed** | The project states plainly that a project is not a filesystem sandbox; `filesystem:read` can read absolute paths outside the project that the running account may read. The same account's `.env`, SSH private keys and the like are therefore within the potential impact. [Authentication boundary](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/internals/environment-auth.md) |
| **Remote pairing grants broad privileges** | The default pairing grant includes the terminal and the ability to start a Full access Agent. The documentation also acknowledges these privileges can be used to create a session with full privileges; if a phone or pairing credential is compromised, the host may be endangered with it. [Authentication boundary](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/internals/environment-auth.md) |
| **Data leaves by default** | Server telemetry is on by default; events go to `ingest.t3.codes`, which keeps a copy and forwards to PostHog. This does not directly imply that it uploads source code, but it cannot be treated as a fully offline tool. [Telemetry code](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/apps/server/src/telemetry/AnalyticsService.ts) |
| **What is installed may not be the version you specified** | The README recommends `curl … \| sh` and `npx t3@latest`, which run whatever is downloaded at the time and are not pinned to this commit. Checking this commit is not the same as verifying the latest installation package. [Installation instructions](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/README.md) |

It also has security design: per-RPC permission checks, one-time pairing and DPoP credential binding. But the project states plainly that the T3 Connect relay signing key remains a link that must be trusted; these mechanisms do not mean a compromised cloud would be harmless. [Authorization code](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/apps/server/src/auth/RpcAuthorization.ts), [Connect trust model](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/internals/t3-connect.md)

If you want to try it, I recommend:

- Use a separate VM or an OS account with no sensitive data, holding only test projects.
- Change the default for new threads to **Supervised**, and confirm no individual project overrides it.
- Use local connections only at first; turn off Network access and T3 Connect.
- Pin the version and check the signature or checksum of the official release; avoid running floating-version install commands directly.
- If you do not accept telemetry, the Server offers `T3CODE_TELEMETRY_ENABLED=false`; this does not turn off connections to the AI providers themselves.

**The conclusion the evidence currently supports: this is a host-control tool that requires a high degree of trust, suitable for isolated trial, not yet enough to vouch for a sensitive main environment.** This time I did not install or run it, did not fully scan dependencies, and did not verify that the release binaries match the source.

## Editors' notes

This section is written by this project's editors and is not part of either review. "Reviewer claim, not independently established" marks a statement we did not check against a primary source.

- **Reading depth differs.** Claude Code says it read only the README and the official documentation. Codex read the documentation and part of the code (telemetry, authorization).
- **Checked against primary sources:** [`permission-modes.md`](https://raw.githubusercontent.com/pingdotgg/t3code/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/user/permission-modes.md) states the initial default is **Full access**; [`.github/SECURITY.md`](https://github.com/pingdotgg/t3code/blob/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/.github/SECURITY.md) gives a security reporting address; [`telemetry.md`](https://raw.githubusercontent.com/pingdotgg/t3code/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/user/telemetry.md) states that events go to `ingest.t3.codes` and on to PostHog, relay traces go to Axiom, and `T3CODE_TELEMETRY_ENABLED=false` turns them off.
- **Correction: Tailscale does not necessarily pass through T3's cloud.** [`remote-access.md`](https://raw.githubusercontent.com/pingdotgg/t3code/7ffc3bb7e80d88327a06d667e4be1bdef85329d3/docs/user/remote-access.md) lists LAN, Tailscale, other VPNs, a public URL, SSH and T3 Connect as separate routes; we found no statement that Network access or Tailscale traffic goes through a T3 cloud relay. The review's sentence that enabling Network access, Tailscale or T3 Connect sends traffic through T3's cloud has documentary support only for T3 Connect.
- **"Prompts, responses and file contents are not collected" is the project's own statement;** neither the reviewers nor we monitored actual traffic.
- **"A well-known developer team" and "no published security advisories" are not security endorsements.** Reputation: reviewer claim, not independently established. No advisory does not mean no vulnerability.
- **The aitoolly link Claude Code cites is a news aggregator, not a primary source;** its suggestion to use Homebrew likewise changes whom you trust and is not inherently safer.
