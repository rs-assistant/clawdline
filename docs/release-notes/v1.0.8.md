# Clawdline v1.0.8

**Pictures an Agent shows you now reach you.** An Agent runs `clawdline image send <picture>` in its
Session, and the picture appears under the reply that sent it — nothing has to be written into the
reply. Before, an Agent stored the picture and wrote a marker into its prose; newer models keep the
prose they write between tool calls only as a summary, the marker went with it, and the picture
never appeared while the Agent believed it had. An upload that names no Session now answers with a
note that nothing was shown, and the guide, the route table and the Sessions and Troubleshooting
pages say how it works.

**A message sent while subagents run is submitted.** While Claude Code runs subagents it lists them
under its message box, and that list's first row begins with the same `❯` as the box. Clawdline read
that row as the input line, never saw the message arrive, and left it typed and unsent
(`send_unsubmitted`); the phone's **Press Enter** did nothing for the same reason, and a notice for a
root with subagents running was held as if a question were on screen. Clawdline now finds the framed
message box wherever it is on the screen.

**Testing a commit on the machine you use.** `clawdline dev install` builds a commit of a clawdline
checkout and runs it in place of the release, with the release's store and Sessions. While it runs,
the top of the session list carries one quiet line — `DEV`, the commit, and whether it is ahead of
the release, behind it or beside it, read from git — with **Release** and the way back to the
release as words. The version panel shows the same standing and names its button for what it does.
The update banner for a new release, and the Cloud list's notice for each machine, take the same
one-line shape; its buttons no longer turn grey on hover.

Also in this release: a new Board item can be assigned as soon as it is created; a scheduled run can
be reopened from its history and is not ended mid-task by its clock; **Delete worktree** deletes the
worktree you chose; a project's health chip opens its site; a Session opened or closed on a machine
shows on the Cloud one-machine list as it is; a machine whose list goes stale keeps its Session
titles; and a queued heavy command no longer keeps its Session from closing.
