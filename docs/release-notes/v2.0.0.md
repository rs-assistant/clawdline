# Clawdline 2.0.0

Clawdline 2.0 brings static HTML reports, more flexible schedules, clearer machine
controls, and smoother everyday navigation. It also retires the built-in
Cloudflare tunnel, so remote-access users should read the migration note below.

## Remote-access migration

The `clawdline tunnel` command, `/v1/tunnel` API, and automatically generated
`trycloudflare.com` address have been removed. Existing tunnel settings are read
as off. Use Clawdline Cloud for paired remote access, or configure Tailscale Serve
for a direct connection over your tailnet. Review remote settings after upgrading;
old tunnel addresses will not be recreated. This removal is why this release is
2.0.0 rather than a 1.x feature release.

Existing Sessions and Projects remain in place. This release does not enable a
new remote-access method on your behalf.

## Reports and schedules

- Open static HTML reports through the authenticated document viewer, including
  validated inline screenshots. Reports stay in an isolated preview and can open
  full screen. Phone document links retain their destination.
- Repeat schedules every chosen number of calendar days.
- Retained Cloud delivery receipts no longer participate in live queue sorting,
  avoiding repeated work as completed items accumulate while preserving receipts.

## Everyday work

- Pairing leads with the action appropriate to the device you are using. Machine
  settings, connection details, names and access controls share a clearer layout.
- Session menus, the sidebar and disclosures open and close without losing their
  place. Loading screens show their layout while the first reading arrives.
- Codex history loads in pages and resumes the selected conversation. Queued work
  stays visible when a terminal changes state.
- Usage filters include configured Projects, background commands are separated
  from agent dispatch counts, and dispatched usage returns to its source Project.
- Project marks support SVG, and interface translations cover more controls and
  recovery states.
- Agents can withdraw their own Notes when attention is no longer needed.

## Reliability and security

- Independent Cloud viewers retain their Session connection when another viewer
  connects, and each phone keeps its own notification subscription.
- Release staging rejects unsafe versions and archive links. Installation cannot
  write through a link outside the archive.
- Untrusted Markdown stays inert, and malformed CSS source maps cannot stall a
  console build.
- Closing an unreadable Session requires an explicit force-close decision.

The next round of Cloud entitlement-read optimization is not included in this
release. Local performance baselines do not establish a production user-capacity
limit.
